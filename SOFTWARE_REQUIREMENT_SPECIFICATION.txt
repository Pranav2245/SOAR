1 INTRODUCTION
1.1 Purpose of the Project
Managing security incidents across modern IT environments is increasingly complex and resource-intensive, involving challenges of alert fatigue, delayed response, and manual triage. SOAR (Security Orchestration, Automation and Response Intelligence) offers a secure, automated, and AI-driven incident response solution built on open-source tools, leveraging Wazuh, TheHive, Cortex, and MISP, augmented with custom machine learning models to address these challenges efficiently by automating threat detection, enrichment, and mitigation.

1.2 Target Beneficiary
• Security Operations Centers (SOCs) requiring scalable, automated incident response.
• IT Administration teams seeking to reduce manual triage and investigation time.
• Organizations needing an integrated, AI-enhanced defense mechanism against complex cyber threats like advanced persistent threats (APTs) and malware.

1.3 Project Scope
SOAR supports secure endpoint monitoring, log collection, automated alert generation, threat intelligence enrichment, and automated active response. It leverages custom AI models (encompassing 30 different attack types) for alert triage, anomaly detection, phishing parsing, and blast radius prediction. The system incorporates a Human-in-the-Loop decision engine to ensure critical incidents are reviewed by human analysts, alongside a self-learning feedback loop to continually improve analytical accuracy over time.

2 PROBLEM STATEMENT
Security Operations Centers are overwhelmed by the increasing volume of security alerts requiring manual review, contextualization, and response. Traditional SIEM systems lack built-in automation and advanced artificial intelligence, leading to alert fatigue, high false positive rates, and dangerous delays in incident mitigation. Manual threat intelligence gathering and playbook execution are error-prone and inefficient. These issues lead to prolonged dwell times for attackers, data breaches, and elevated operational costs, making a modern, AI-integrated SOAR solution necessary.

3 LITERATURE REVIEW
The evolution of incident response spans from manual log review to centralized SIEMs, and currently to SOAR platforms. Traditional SIEMs offer visibility but suffer from requiring manual intervention for every alert. Commercial SOAR platforms offer automation but often come with high licensing costs and black-box algorithms. Cloud-native and open-source architectures using Wazuh, TheHive, and Cortex promote customization and cost efficiency. Research underscores the critical importance of integrating machine learning into these pipelines to reduce false positives and speed up the triage process, allowing analysts to focus on complex threat hunting instead of repetitive tasks.

• Traditional Manual Analysis:
  - Advantage: High control over response actions.
  - Drawback: Extremely slow, non-scalable, and prone to human burnout (alert fatigue).

• Commercial SOAR (e.g., Splunk Phantom, Cortex XSOAR):
  - Advantage: Deep integrations and enterprise support.
  - Drawback: Expensive licensing fees, vendor lock-in, and limited ability to inject custom, self-learning AI models.

• Open-Source SOAR (Wazuh + TheHive):
  - Advantage: Cost-effective, extensible, and allows seamless integration of custom Python-based AI microservices and localized threat intelligence (MISP).
  - Drawback: Requires significant upfront configuration and infrastructure management.

4 PROJECT DESCRIPTION
4.1 Reference Algorithm
The SOAR architecture integrates multiple specialized components: Wazuh for rule-based detection and agent management; TheHive for case management; Cortex for observable enrichment; and MISP for threat intelligence. The intelligence layer utilizes machine learning algorithms: XGBoost for Multi-class ML Triage (predicting confidence scores), Isolation Forest for Anomaly Detection, K-Means with TF-IDF for Semantic Log Clustering, and Graph algorithms for Blast Radius Prediction, all orchestrated via Python scripts and APIs.

4.2 Characteristics of Data
The system processes structured and unstructured security data including system logs (syslog, Windows Event Logs), network traffic flow records, File Integrity Monitoring (FIM) events, and parsed email headers/bodies. Data encompasses 30 distinct attack profiles (e.g., SSH Brute Force, Pass-the-Hash, DNS Tunneling, Zero-Day Exploits) alongside normal operational baselines.

4.4 Project Features
• Real-time log ingestion and rule-based threat detection (Wazuh).
• Automated alert escalation and case creation (TheHive API integration).
• Automated observable enrichment and threat intelligence lookup (Cortex & MISP).
• 8 Specialized AI Modules (ML Triage, Phishing NLP, Anomaly, Log Clustering, Blast Radius, Playbook Optimizer, Report Generator, LLM Commander).
• Human-in-the-loop workflow for Major Incidents.
• Self-learning automated retraining based on analyst feedback.
• Automated 10-section PDF Incident Report generation.

6 METHODOLOGY
• Requirements gathered focusing on the need to automate repetitive SOC tasks and reduce Mean Time To Respond (MTTR).
• Designed a containerized architecture integrating Wazuh, TheHive, Cortex, and MISP.
• Developed Python integration scripts (e.g., wazuh_to_thehive.py) to map events between tools.
• Developed and trained 8 specialized AI modules using Python data science libraries (scikit-learn, XGBoost, pandas).
• Expanded synthetic training data to cover 30 distinct cybersecurity attack types.
• Implemented a strict decision engine (Human-in-the-Loop) distinguishing between minor automated fixes and major human-required escalated cases.
• Deployed using docker-compose and tested end-to-end using mock attacks (e.g., simulated brute force and reverse shells).
